Static recompilation · on the core of PCSX2

PlayStation 2 games as native applications

PS2Native translates a game's code to C++ ahead of time and compiles it for the machine it will run on. The console around that code is the core of PCSX2.

Source on GitHub See how it works

In development. There is nothing here for players yet.

01 · The idea

Compile the game. Keep the machine.

The aim is a standalone game: no emulator to install, nothing to set up. A PlayStation 2 game talks to the console's hardware directly, though, and rebuilding that hardware is where the first PS2Native stalled. So this one translates the game's code and leaves the hardware to the emulator that has already solved it.

Translated ahead of time

The game's code becomes C++ before the game ever runs: one C++ function for each function of the game, compiled by an ordinary compiler. The rule for a finished game is that no recompiler for PS2 code ships inside it.

On the core of PCSX2

Graphics, sound, storage, timing and the console's other processors are PCSX2's, pinned to one version and unmodified. The translated code takes the place of PCSX2's recompiler for the console's main processor.

Your game, your BIOS

You provide your own game and your own BIOS dump. Neither is included here, and nothing generated from them is.

Stop reinventing what PCSX2 has already solved, while preserving the goal of genuine native recompilation.

02 · How it works

From a disc to native code

Once, on your own machine, the game's executable goes through the recompiler and a C++ compiler. From then on the compiled code runs as the console's main processor, inside PCSX2's core.

Code that no one saw coming

Some code does not exist until the game runs, and some is reached in ways no analysis can see. It is interpreted once, reported and captured, and the next build compiles it. Nothing is interpreted silently.

Every label is a way in

A block of code can begin at any label: after a call returns, or when an interrupt hands control back. L_ is where one begins, and there the runtime checks that the code in memory is still the code that was compiled. M_ is where a block that began earlier runs on through.

The delay slot, as on the console

The branch is decided first. The instruction after it runs either way, and only then does the branch take effect.

Time, in eighths of a cycle

Nine for most instructions, eleven for the branch: 65 for this block. They are added where PCSX2's recompiler would add them, and that is where the rest of the machine is given its turn.

04 · The same run

Not close to the stock run. The same run.

Again and again, PCSX2 lets the console's second processor catch up with the main one. At each of those moments a run can be written down: where the main processor is, its cycle count, hashes of its registers. Two runs with the same record took the same path through the program at the same times.

38,478,822

such moments in the first 4,200 frames of Killzone. The compiled run and the run under stock PCSX2 are the same at every one. Their records, 3 GB each, are the same file byte for byte.

  • 4,199frames fingerprinted, and the same picture at every one of them.
  • 47,705,744event tests at which the compiled run is also the interpreted run.
  • 59 of 63test programs are the stock run too, at every such moment. The other four are listed, each with its cause.

Measured on 2026-11-11, on Windows

Those 4,200 frames are the copyright screen, the developer's logo, a memory card prompt and the intro film. A longer run goes through the menus into the first level and plays there for three and a half minutes: the two are at the same place at the same cycle count at every one of its 93,221,937 moments, and they show the same picture at each of the 1,750 frames compared, one in every ten. Where PS2Native follows the console on purpose, because a recording shows PCSX2's recompiler wrong, a run does differ from the stock run, and each such place is listed with its cause.

06 · What is static

What is translated today, and what is not yet

The rule is that no recompiler for PS2 code ships in a finished game. Today that holds for the game's own code. Everything else is labeled for what it is, in this order of work.

1 · MAIN PROCESSOR

The game's code

EE

Static

Translated ahead of time. In the first 4,200 frames of Killzone not one instruction of the executable is interpreted.

2 · MAIN PROCESSOR

The BIOS kernel

EE

Static

System calls, interrupts and threads are the BIOS's own code, translated ahead of time on your machine from your own dump. Of it, 51 instructions at boot are interpreted. In a finished game it will be a file of its own beside the game.

3 · VECTOR UNITS

Micro programs

VU0, VU1

Stand-in

PCSX2's recompiler runs them for now. It is a temporary stand-in: a static translator is to take its place, once it has been validated against it.

4 · SECOND PROCESSOR

The IOP's modules

IOP

Stand-in

PCSX2's recompiler, for now, under the same rule. PCSX2's recompiler for the main processor is never a stand-in.

The hardware stays PCSX2's

Graphics, sound, DMA, timers, the disc, pads and memory cards are not rebuilt. That is the part the project does not reinvent.

No finished game on a stand-in

Packaging does not exist yet. When it does, it is to refuse a release while a stand-in is in use, or mark the result a development build.

07 · Decisions

Rules the project holds itself to

Every decision is written down, with the maintainer's own words and how they were read. These are the ones that shape the rest.

ADR 0002

Static processors on PCSX2's core

The game's code is translated ahead of time and acts as the console's processors. PCSX2's core is the machine. A BIOS is required.

Read the record → ADR 0003

No JIT in a generated game

No recompiler for PS2 code ships in a finished game. Code not seen at build time is interpreted once, reported, captured and rebuilt.

Read the record → ADR 0005

Never further from the console than PCSX2

On no line of a console-recorded test may stock PCSX2 be right and PS2Native wrong. Every remaining difference is listed with its cause.

Read the record → ADR 0007

The BIOS is translated on your machine

From your own dump, as a file of its own beside the game. It is never in the repository and never in anything PS2Native distributes.

Read the record → ADR 0011

Time is counted as PCSX2's recompiler counts it

A run on PS2Native is the stock run, moment for moment. A difference is a defect to find, not a property to argue about.

Read the record → The brief

Never invent a result

No invented test or benchmark results, and no failing test skipped silently. A claim about speed or compatibility needs a measurement that can be repeated.

08 · Roadmap

Prove the architecture before building the application

Five phases. Each one ends with a stop, and the next begins only with the maintainer's approval.

  1. Phase 1Done · 2026-11-10

    Feasibility assessment

    The first PS2Native, PCSX2 and three other recompilation projects, read at the source. The recommendation: statically recompiled code as the processors, PCSX2's core as the machine, a BIOS supplied by the user.

  2. Phase 2Done on Windows · 2026-11-11

    Proof of concept

    Every one of 63 test programs runs with its own code compiled ahead of time, the same as its interpreted run at every event test. The Linux step is deferred by the maintainer: its scripts are written and have never been run.

  3. Phase 3In progress

    The first real game: Killzone

    The European release, from the maintainer's own copy. Nothing of the game is in the repository, and nothing generated from it.

    • G0BaselineDone as far as the intro film
    • G1The interpreter as referenceDone for the first 4,200 frames
    • G2The game's code compiledDone
    • G3The compiled gameDone for the first 4,200 frames
    • G4Further into the gameDone as far as the first level: by script, and played by the maintainer in a window, with sound and a controller, on Windows
    • G5Measurement and reportDone as far as the first level: 1.35 times stock PCSX2's time, all of it in the game's own code
    • G6SpeedDone: the run into the first level takes 1.21 to 1.23 times stock PCSX2's time, from 1.35, and is still the stock run
    • G7VU0's instructionsDone: the game's VU0 instructions are PS2Native's own, the same as PCSX2's recompiler in every case the self-test tried, and the run into the first level is still the stock run
    • G8The BIOS's EE codeDone: the BIOS's code that runs on the main processor is compiled ahead of time from the user's own dump, but for 51 instructions at boot; the run into the first level takes 1.18 times stock PCSX2's time and is still the stock run
    • G9VU0's instructions in compiled codeDone: compiled code carries them out itself where their block lets it; the run into the first level takes 1.19 times stock PCSX2's time, from 1.21, and is still the stock run
    • G10PerformanceUnder way: profile-guided optimization, loops that have reached a fixed point no longer run their identical times round, compiled code carries out the COP2 instructions and its calls through a register itself, and the way loads and stores seldom take is short; the run into the first level takes 1.04 times stock PCSX2's time, from 1.18, and is still the stock run
  4. Phase 4Needs its own approval

    The application

    A wizard that takes a game and gives back a native application. Every setting is fixed when the game is built, and the result shows no emulator's interface. None of it exists yet.

    1. Choose the game
    2. Give the BIOS
    3. Accept the defaults
    4. Recompile
    5. Package
  5. Phase 5Later

    Maintenance

    Automated regression tests, compatibility reports, and checks against each new version of PCSX2 before it is taken up.

Required

Windows x64

Built and run. Everything measured on this page was measured here.

Required

Linux x64

Its scripts are written and have never been run. Nothing is known to work there yet.

Optional

macOS, Android, iOS

Bounded by what PCSX2 supports. Nothing is built or tested for them.
