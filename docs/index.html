Static recompilation · on the core of PCSX2

PlayStation 2 games as native applications

PS2Native translates a game's code to C++ ahead of time and compiles it on your own computer, into a folder that plays the game. The console around that code is the core of PCSX2.

Download 0.1 Source on GitHub

0.1, a pre-release (2026-11-19): tried with five games on Windows, and on Linux under WSL 2

01 · The idea

Compile the game. Keep the machine.

The aim is a standalone game: no emulator to install, nothing to set up. A PlayStation 2 game talks to the console's hardware directly, though, and rebuilding that hardware is where the first PS2Native stalled. So this one translates the game's code and leaves the hardware to the emulator that has already solved it.

Translated ahead of time

The game's code becomes C++ before the game ever runs: one C++ function for each function of the game, compiled by an ordinary compiler. The rule for a finished game is that no recompiler for PS2 code ships inside it.

On the core of PCSX2

Graphics, sound, storage and timing are PCSX2's, pinned to one version and unmodified. The translated code takes the place of PCSX2's recompilers for the console's two processors and its two vector units.

Your game, your BIOS

You provide your own game and your own BIOS dump. Neither is included here, and nothing generated from them is.

Stop reinventing what PCSX2 has already solved, while preserving the goal of genuine native recompilation.

  1. The game
  2. The BIOS
  3. The settings
  4. The recompile

The disc image in any format PCSX2 plays, PCSX2's own settings pages, a recompile of a few minutes, and a folder that plays the game, started from the program named after it. Code a session meets for the first time runs interpreted, slower, and is compiled when you close the game.

What it needs

  • Your own game, and a BIOS dumped from your own console
  • A processor with SSE4.1 (Intel from 2008, AMD from 2011)
  • A graphics driver with Vulkan, or another renderer chosen in the game's settings
  • About 1 GB of disk for each game on Windows, 1.5 GB on Linux: each game's folder has its own copy of the compiler

What to know

  • Tried with five games: Killzone, 007: Agent Under Fire, Gran Turismo 3: A-Spec, Jak and Daxter and Silent Hill 3, the European releases. Every other game is untried and may not work
  • The programs are not code-signed: Windows warns the first time
  • A game's folder holds code translated from your game and your BIOS. It is yours alone: do not share it

From a disc to native code

Once, on your own computer, the wizard takes the game's executables from its disc image, translates them to C++ and compiles them with the compiler it brings. From then on the compiled code runs as the console's processors, inside PCSX2's core.

Code that no one saw coming

Some code does not exist until the game runs: some games load their code from their data. Some is reached in ways no analysis can see. It is interpreted, slower, and a notice over the picture says so; when the game closes, its folder compiles it, in a window that can leave it for later. A game never starts with anything left to compile, and nothing is interpreted silently.

Every label is a way in

A block of code can begin at any label: after a call returns, or when an interrupt hands control back. L_ is where one begins, and there the runtime checks that the code in memory is still the code that was compiled. M_ is where a block that began earlier runs on through.

Registers in locals

g2 is $v0, g8 $t0, g9 $t1: the console's registers in local variables, which the compiler keeps in the processor's own. Those the block changed are put back before it ends, where the rest of the machine may look at them.

The delay slot, as on the console

The branch is decided first. The instruction after it runs either way, and only then does the branch take effect.

Time, in eighths of a cycle

Nine for most instructions, eleven for the branch: 65 for this block. They are added where PCSX2's recompiler would add them, and that is where the rest of the machine is given its turn.

05 · The same run

Not close to the stock run. The same run.

Again and again, PCSX2 lets the console's second processor catch up with the main one. At each of those moments a run can be written down: where the main processor is, its cycle count, hashes of its registers. Two runs with the same record took the same path through the program at the same times.

07 · What is static

What is translated, and what is not yet

The rule is that no recompiler for PS2 code ships in a game. A game's folder compiles everything its sessions have met: the game's own code, the BIOS's, the programs on the vector units and the second processor's modules. What a session meets for the first time runs interpreted, a notice over the picture says so, and it is compiled when the session ends.

1 · MAIN PROCESSOR

The game's code

EE

Static

Translated ahead of time. In the first 4,200 frames of Killzone not one instruction of the executable is interpreted.

2 · MAIN PROCESSOR

The BIOS kernel

EE

Static

System calls, interrupts and threads are the BIOS's own code, compiled on your computer from your own dump, into a module of its own beside the game's. Of it, 51 instructions at boot are interpreted. A new game's folder starts with what the other games' folders met of it.

3 · VECTOR UNITS

Micro programs

VU0, VU1

Static

Translated ahead of time, each block by what it does, wherever the game writes it. In the run into Killzone's first level not one block of them is interpreted, and none runs on PCSX2's recompiler.

4 · SECOND PROCESSOR

The IOP's modules

IOP

Static

Translated ahead of time, block by block, each found by its instructions wherever the IOP's kernel loads it. In the run into Killzone's first level not one block of them is interpreted, and none runs on PCSX2's recompiler.

The hardware stays PCSX2's

Graphics, sound, DMA, timers, the disc, pads and memory cards are not rebuilt. That is the part the project does not reinvent.

No game on a stand-in

Until PS2Native had translators of its own for them, PCSX2's recompilers for the vector units and the second processor stood in, labeled as that; its recompiler for the main processor never did. None is in use now. In a game's folder how each processor runs is fixed, and the runtime refuses a settings file that changes it.

08 · Decisions

Rules the project holds itself to

Every decision is written down, with the maintainer's own words and how they were read. These are the ones that shape the rest.

ADR 0002

Static processors on PCSX2's core

The game's code is translated ahead of time and acts as the console's processors. PCSX2's core is the machine. A BIOS is required.

Read the record → ADR 0003

No JIT in a generated game

No recompiler for PS2 code ships in a finished game. Code not seen at build time is interpreted once, reported, captured and rebuilt.

Read the record → ADR 0005

Never further from the console than PCSX2

On no line of a console-recorded test may stock PCSX2 be right and PS2Native wrong. Every remaining difference is listed with its cause.

Read the record → ADR 0007

The BIOS is translated on your machine

From your own dump, as a module of its own beside the game's. It is never in the repository and never in anything PS2Native distributes.

Read the record → ADR 0011

Time is counted as PCSX2's recompiler counts it

A run on PS2Native is the stock run, moment for moment. A difference is a defect to find, not a property to argue about.

Read the record → The brief

Never invent a result

No invented test or benchmark results, and no failing test skipped silently. A claim about speed or compatibility needs a measurement that can be repeated.

Read the brief → ADR 0028

A game is made on your computer

PS2Native brings its own compiler. A game's code is compiled on your computer into modules that a ready-made runtime loads, and the game is a folder that plays it.

Read the record → ADR 0040

Compiled before it plays

What a session meets for the first time is compiled when the game closes, in a window that can leave it for later. A game never starts with anything left to compile.

Read the record → ADR 0043

Measured as users get it

Speed is measured in a game's folder, as users get it, on the maintainer's own sessions run again against stock PCSX2. A change is kept only if it gains.
